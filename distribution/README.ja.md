# ERForge

DB スキーマの ER 図・テーブルカタログを、Git で管理しやすい形式で保守するツールです。

https://github.com/artistrytech/er-forge

## 同梱物

| ファイル | 説明 |
|---|---|
| `erd-server.jar` | サーバーモード本体（Java 17 以上が必要） |
| `index.html` | ビューア。ブラウザで直接開ける単一の HTML |
| `erd.bat` / `erd.sh` | 起動スクリプト（引数なしでサーバー起動、`export` で閲覧用 ZIP の書き出し） |
| `drivers/` | JDBC ドライバの置き場（初期は空。**全ワークスペース共通**）。逆生成画面から主要 DB のドライバをダウンロードできる。手動で JAR を置くことも可能（`drivers/README.txt` 参照） |
| `THIRD-PARTY-NOTICES.txt` | 同梱しているオープンソースソフトウェアの著作権・ライセンス表示 |
| `.gitignore` / `.gitattributes` | このディレクトリ配下の Git 運用設定。展開したらそのままコミットする |

## セットアップ

1. この ZIP の中身を、プロジェクトリポジトリの中の好きなディレクトリに展開する
2. 展開したディレクトリをそのままコミットする

   ```
   git add erd
   git commit -m "ER 図管理ツールを追加"
   ```

**ディレクトリ名は自由です**（このドキュメントでは `erd/` を例にします）。サーバーは自分が
置かれたディレクトリをプロジェクトルートとして動き、同梱の `.gitignore` / `.gitattributes` も
そのディレクトリからの相対で効くため、名前にも階層の深さにも依存しません。

`.gitignore` を書き足す作業はありません。除外すべきものは同梱の `.gitignore` がすべて持っており、
ツールが作るファイルは（個人データも含めて）すべてこのディレクトリの中に収まります。

## Git 管理の方針

**展開したディレクトリの中身は原則すべて Git 管理します**（`erd-server.jar` と起動スクリプトを含む）。
メンバーが `git pull` するだけで、全員が同じ版のツールとデータを使える状態にするためです。
バージョンアップは新しい ZIP を同じ場所に上書き展開し、その差分をコミットします
（**ディレクトリごと消してから展開し直さないでください。** スキーマデータと個人データも消えます）。

| 対象 | Git 管理 | 備考 |
|---|---|---|
| `index.html`・`erd-server.jar`・`erd.sh`・`erd.bat` | ✓ | `.gitattributes` でバイナリ指定し diff ノイズを抑制 |
| `workspaces.js`・`config.js`・`workspace-*/data/**` | ✓ | レビュー対象 |
| `drivers/README.txt` | ✓ | ドライバの置き方の説明 |
| `.local/` | ✗ | 個人データ。DB 接続情報（パスワードは明示保存時のみ）・逆生成の適用前および AI 書き込み前のバックアップ・AI 連携（MCP）の設定とトークン・個人設定 |
| `drivers/*.jar` | ✗ | ライセンスの都合で各自がダウンロードする |

## 使い方

### 編集者（サーバーモード。Java 17 以上が必要）

`erd.bat`（Windows）または `./erd.sh`（macOS / Linux）を実行すると、
`http://127.0.0.1:5321/` でサーバーが起動し、ブラウザが自動で開きます。

初回はワークスペースの作成画面が表示されます。ワークスペースは 1 データベースにつき 1 つ作成される想定で、
ID（英数・ハイフン・アンダーバー。省略時は `default`）と表示名を入力すると
`workspace-<ID>/` が作られます。複数の DB を扱う場合は、アプリタイトル横の
プルダウンからワークスペースの追加・切り替えができます。

続けてブートストラップ画面が表示されます。「サンプルデータを取り込む」を選ぶと、
約 30 テーブルの完成済みサンプルが `workspace-<ID>/data/` に書き出され、DB なしで機能を試せます。

編集後は `workspaces.js`・`workspace-*/data/**`
（ドライバ設定を変えた場合は `config.js` も）をコミット・プッシュしてください。

### 閲覧者（静的モード。Java 不要）

`git pull` して `index.html` をブラウザで開くだけです。
ER 図の閲覧・検索・テーブルカタログがそのまま使えます。

### Git を使わない相手に渡す（閲覧用 ZIP）

閲覧に必要なものだけをまとめた ZIP を作れます。受け取った人は、展開して `index.html` を
ブラウザで開くだけです（Git も Java も要りません）。

```
ERForge-viewer-20260806-2312.zip
├── index.html
├── workspaces.js
├── workspace-<ID>/data/**      選んだワークスペース分
└── THIRD-PARTY-NOTICES.txt
```

**接続情報（`.local/`）・JDBC ドライバ・`erd-server.jar` は入りません。** 社外に渡す場合でも
DB の認証情報が混ざる心配はありませんが、**選んだワークスペースのスキーマの内容はすべて入る**
点はご注意ください。

#### 画面から（サーバーモード）

ヘッダの **ツール（レンチ）→ [閲覧用 ZIP を書き出す]** を選ぶと、ファイル名と含めるワークスペースを
指定して書き出せます（ブラウザのダウンロードとして保存されます）。同じ内容を作るコマンドも
画面に表示されるので、あとから定期実行に切り替えたいときはそれをコピーしてください。

#### コマンドから（サーバー起動なしで使えます）

```
erd.bat export      （Windows）
./erd.sh export     （macOS / Linux）
```

ZIP はこのディレクトリに作られます。オプションはどちらも省略できます。

| オプション | 既定 | 例 |
|---|---|---|
| `--prefix=<名前>` | `ERForge-viewer` | `erd.bat export --prefix="売上 ER図"` |
| `--workspaces=<a,b>` | 全ワークスペース | `erd.bat export --workspaces=sales,billing` |

ファイル名は `<名前>-<日時>.zip` になります。名前には日本語や空白も使えます
（`\ / : * ? " < > |` などファイル名に使えない文字は指定できません）。

### AI エージェントから読み書きする（MCP。サーバーモード）

Claude Code などの AI エージェントから、[MCP](https://modelcontextprotocol.io/) で ERForge に接続できます。
接続先はこのサーバーなので、**サーバーを起動している間だけ**使えます。

#### 有効にする

1. ヘッダの **設定（歯車）→ [AI 連携（MCP）]** を開く
2. **[MCP を有効にする]** をオンにし、**[発行]** でトークンを作る
3. 使っている AI クライアントのタブ（Claude Code / Codex / Cursor / GitHub Copilot）を選び、
   表示された設定を **[コピー]** して、そのクライアントの設定ファイルに貼る
   （貼り付け先のファイル名は画面に出ます）
4. AI クライアント側で接続し直す（Claude Code なら `/mcp` から reconnect）

**トークンを表示できるのは発行した直後だけです。** 画面を閉じると末尾数文字しか見えなくなります。
分からなくなったら **[再発行]** してください（古いトークンはその場で使えなくなります）。

接続できているかは同じ画面の **最終アクセス** で確認できます。何も出ないときは、
サーバーが起動しているか、クライアント側で接続し直したか、ポートが変わっていないかを確認してください
（ポートは起動のたびに変わることがあります。その場合は設定を貼り直します）。

> **貼り付けた設定ファイルにはトークンが含まれています。** `.mcp.json` などをリポジトリにコミットしないでください。
> ERForge 側のトークンは `.local/` にあり、Git には含まれません。

#### できること

| | 内容 |
|---|---|
| **読む**（常に） | テーブル一覧・定義・リレーション・カラム辞書・ER 図のページ構成。コード生成や SQL 作成の文脈として AI に渡せます |
| **書く**（**[書き込みを許可する]** をオンにした場合のみ） | 論理名・注記・タグ・色、論理制約（DB に無い関係・一意性）、ページの作成とテーブルの配置、カラム辞書、無視リスト |
| **書けないもの** | カラム・型・主キー・外部キー・索引。これらは DB から取り込む物理情報で、AI に書かせても次の取り込みで上書きされてしまうため、許可しても書けません |

ER 図の配置は、**どのテーブルを同じページに置くかを AI が決め、座標はサーバーが自動で計算**します。
たとえば「ソースコードを読んで、業務ドメインごとにページを分けて ER 図を作って。コード上は参照しているのに
DB に外部キーが無い箇所は論理外部制約として登録して」といった頼み方ができます。

**書き込みを許可する前にコミットしておくことをおすすめします。** AI の変更はすべて
`workspace-*/data/**` のテキストファイルに反映されるので、`git diff` で確認でき、気に入らなければ戻せます。
念のため、AI からの書き込みの前には `.local/` にバックアップも取られます（直近 3 世代のバックアップを保持します）。

### スキーマ情報の書き出し（両モード共通）

ヘッダの **ツール（レンチ）→ [スキーマ情報を JSON で書き出す]** で、全テーブルの定義と
メタデータ（論理名・タグ・色・注記・論理制約）・リレーションを 1 つの JSON
（`schema-<ワークスペースID>.json`）にまとめて保存できます。ページ情報と ER 図の配置は含みません。
カラム辞書の論理名・タグは各テーブルの `meta.columns` にまとめて出力するため、受け取った側で
「テーブル個別 → 辞書」の解決をする必要はありません（辞書側の色は表示用の属性なので出力しません）。
出力は整形なしの最小サイズの JSON で、他のツールに渡すための形式です。
