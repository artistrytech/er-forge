# 詳細設計: R-01〜R-05（テーブル画面の連続表示とドキュメントモード）

対象機能: **R-01 連続表示とドキュメントモード / R-02 表示モードの切替と記憶 / R-03 左パネルとの連動 / R-04 カラム属性のポップアップ / R-05 注記の直接編集**
関連: B-03〜B-05（左パネル）、O-02（テーブル詳細）、O-03（テーブル編集）、P-01〜P-05（論理名の解決）、E-11（確定＝即時保存の先例）、I-01〜I-03（ページ管理 = 閲覧ルートからの即時書き込みの先例）
設計書: [1_architecture.md](../1_architecture.md) §4.4（ルーティング）/ §6（ロード設計）/ §8.4（`baseHash`）/ §9.1（ER図とカタログの分離）

## 0. この設計が解く問題

テーブル詳細画面（O-02）は「1テーブルの全情報」を出す画面であり、**複数のテーブルを続けて読む**用途には向かない。
テーブルを1つ読むたびに左パネルで次を選ぶ必要があり、カラム表も型・NULL・既定値・コメント・タグ・注記を横に並べるため、
**物理名・論理名・注記だけを追って設計の意図を読む**という「ドキュメントとしての一読」ができない。

この設計は、テーブル画面の右ペインを**左パネルに並んでいるテーブル群を上から順に描く1本のスクロール文書**にし、
1テーブルの中身の密度を「詳細 / ドキュメント」で切り替えられるようにする。

- **詳細**: 従来の1テーブルの全情報（TableInfo）をそのまま縦に連ねる。1件表示だったものが連続表示になるだけで、中身は変えない
- **ドキュメント**: 各テーブルを「見出し＋注記＋カラム表（物理名・論理名・タグ・注記）」に絞る。型や PK/FK/NULL は消さず、ポップアップに退避する

範囲・スクロール追随・切替・左パネルとの連動は両モードで共通にし、**見た目の骨組み（見出し・タグ・行の色・表）も詳細と同じ部品を使う**。
読んでいて気付いた注記の不足は、ドキュメントモードではその場でダイアログから直せるようにする。

### 0.1 不変条件

| # | 不変条件 | 破られたときに起きること |
|---|---|---|
| INV-1 | **範囲は左パネルが決める。** ドキュメントモードは「左パネルに今並んでいるテーブル」を上から順に描くだけで、範囲を選ぶ UI を自前で持たない | 左パネルと右ペインで別々の絞り込みを持ち、「左に無いテーブルが右に出る」食い違いが生まれる（O-02 の直リンク時に起きた問題と同じ） |
| INV-2 | **論理名・注記の解決は詳細（TableInfo）と同じ関数を使い、見出し・タグ・行の色も同じ部品（`TableMetaHeader` / TableInfo のスタイル）を使う** | 詳細では辞書の論理名が出るのにドキュメントでは未設定になる、といった不一致が起きる。見た目が二系統になると、切り替えたときに別の画面に見える |
| INV-3 | **注記の保存は `saveTableMeta` の経路（読み直し → `baseHash` → `PUT /tables/<id>`）に載せる。専用 API を足さない** | 保存経路が3本目になり、`index.js` 再生成・バックアップ・競合検出の抜けが生まれる。既存の PUT は全文置換だが、直前に読み直したものを1フィールドだけ変えて書くため、部分更新 API と結果は同じ |
| INV-4 | **ドキュメントモードは閲覧ルートであり、編集セッションを開始しない。** 書けるのは注記（テーブル / カラム）だけで、確定＝即時保存 | 「編集ルートに入って初めて編集が始まる」（§4.4）の原則が崩れ、フォームの途中状態が残る。ページ管理（I-01〜I-03）と同じく、**1ダイアログ＝1回の書き込み**に限定することでこの原則と両立させる |
| INV-5 | **DOM は範囲の全テーブル分を持つ**（遅延描画で間引かない）。重さは `content-visibility` で吸収する | 途中を描かない仮想化にすると、アンカーへのスクロール・ブラウザの検索（Ctrl+F）が成立しない。「文書として読む」機能でこの2つを失うのは本末転倒 |

## 1. 画面と状態

### 1.1 遷移

```
#/tables/<id>          詳細（連続表示。O-02）  ◄──[詳細 | ドキュメント]──►   #/tables/doc/<id>   ドキュメント（連続表示）
                                                                              │
#/tables               最後の表示モードへ振り替える（R-02）                      └─ 注記ダイアログ（R-05。確定＝即時保存）
#/tables/doc           同上（ドキュメント固定。tableId は最後に見たもの）
```

- どちらのルートも同じコンポーネント（`TablesDocument`）で、URL の `<id>` は**スクロール先**を表す。
  右ペイン上部に「詳細 / ドキュメント」のセグメント切替を置く。**両方とも実リンク**（X-04）で、
  切替先の `<id>` は**読んでいる位置のテーブル**（§3.2 のスクロール追随）。
- 左パネルはそのまま（ページ / 全て / 検索の3レーン）。テーブル画面用のインスタンスを共用する。
- 詳細のセクションは従来の詳細画面と同じ（見出し＋TableInfo＋削除の導線）。
- ヘッダの編集ペン（O-03 への入口）は詳細・ドキュメントの両方に出し、**読んでいる位置のテーブル**を対象にする。
  編集を終えた戻り先は**最後に使っていた表示モード**（`tablesView`）のルート。
- ドキュメントのセクションの見出しの操作は (i) だけ、注記のペンは注記の横。セクション内にはテーブル編集への
  導線を置かない（ヘッダのペンと左パネルの行の近道から行ける）。

### 1.2 ルート

| ルート | 画面 | 備考 |
|---|---|---|
| `#/w/<ws>/tables/<tableId>` | 詳細（連続表示）。`<tableId>` の見出しへスクロール | 従来と同じ URL。存在しない ID は「見つかりません」 |
| `#/w/<ws>/tables/doc` | ドキュメント。最後に見たテーブルの位置へ | `#/tables/doc/<lastTableId>` へ `replace` |
| `#/w/<ws>/tables/doc/<tableId>` | ドキュメント。`<tableId>` の見出しへスクロール | 範囲に無ければ、そのテーブルの載っているページを左パネルが選び直し、範囲が変わった時点でそこへ運ぶ（O-02 の直リンクと同じ） |

`doc` はセグメントとして予約する（`#/tables/new` と同じ扱い）。テーブル ID は `schema.name` 形式のため衝突しない。

### 1.3 状態

| 状態 | 置き場所 | 理由 |
|---|---|---|
| 表示モード（`detail` / `doc`） | `localStorage`（`erd-tables-view`。ワークスペースで分けない） | 個人の読み方の好み。`nameDisplay` と同じ扱い |
| 範囲（テーブル ID の配列） | `appStore.tablesPanelList`。左パネル（tables スコープ）の各レーンが `useEffect` で書く | INV-1。パネルは常時マウント（回答2）なので常に最新 |
| 読んでいる位置（スクロール追随のテーブル ID） | `appStore.docActiveTableId` | 左パネルの選択ハイライトと切替リンクの `<id>` に使う。**URL は書き換えない**（履歴を汚さない・スクロールのたびに再描画させない） |
| `lastTableId` | 既存（sessionStorage） | 詳細画面と同じく、ドキュメントで読んでいる位置でも更新する。詳細へ切り替えたときに同じテーブルが開く |
| 注記ダイアログ | コンポーネントのローカル状態 | 1回で完結するため |

## 2. R-01 連続表示とドキュメントモード

### 2.1 範囲の決め方（INV-1）

左パネルのレーンごとに、**一覧に描いている順序のまま**採用する。

| レーン | 範囲 |
|---|---|
| ページ | 選択ページのテーブル（ページ内の並び順）。「未配置」を選んでいれば未配置トレイのテーブル |
| 全て | テーブル名フィルタの結果（名前昇順） |
| 検索 | ヒットしたテーブル（スコア順。同じテーブルはカラム一致が複数あっても1回） |

範囲の見出し（「ページ: 受注」「全て: "order"（12）」「検索: 金額（5）」）を右ペイン上部に出し、**何を読んでいるのかを示す**。
範囲が 0 件なら「左の一覧にテーブルがありません」を出す。

範囲が変わったら（レーン切替・フィルタ入力・ページ選択）文書を描き直す。**読んでいた位置のテーブル**（`docActiveTableId`。まだ無ければ URL の `<tableId>`）が新しい範囲に含まれていればそこへ、無ければ**先頭へ戻す**。着地直後は左パネルの公開より先に描かれるため、URL の `<tableId>` がこの経路で効く（直リンクから左パネルがページを選び直すケース。O-02 と同じ）。

### 2.2 1テーブルの構成（ドキュメント）

```
┌──────────────────────────────────────────────────────────────┐
│ 受注 (orders)   public.orders                          (i)  │  ← 詳細と同じ見出し（.catalog-header: 表示形式に従う名前 + ID）
│ VIEW ・ DB コメント ・ tags                                     │  ← 詳細と同じ TableMetaHeader（種別・コメント・タグ）
│ 注記: 顧客からの注文。1注文 = 1レコード。キャンセルは …  [ペン]  │  ← meta.notes（pre-wrap。無ければ「注記なし」を薄く）
│                                                              │
│ カラム                                                        │
│ ┌────────────┬──────────────┬────────┬────────────────────┐  │
│ │ 物理名  (i) │ 論理名        │ タグ    │ 注記           [ペン]│  │
│ ├────────────┼──────────────┼────────┼────────────────────┤  │
│ │ id      (i) │ 注文ID        │        │                      │  │
│ │ user_id (i) │ 顧客ID 辞書   │ pii    │ 退会後も残す（監査用）│  │
│ │ status  (i) │ （未設定）    │ enum   │ 1:受付 2:出荷 …      │  │
│ └────────────┴──────────────┴────────┴────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

- 見出し・種別バッジ・タグ・注記の行・カラム表の行の色は**詳細と同じ部品**（`.catalog-header` / `TableMetaHeader` / TableInfo のスタイル）を使う（INV-2）。
  名前は詳細と同じく表示形式（L）に従う。物理名は ID として常に併記されるので、論理名だけの設定でも読み比べられる。
- カラム表は物理名・論理名・タグ・注記の4列。タグは辞書 ∪ 個別（P-12）で、詳細と同じピル。
- 論理名の出どころ（個別 / 辞書 / 未設定）は詳細と同じバッジ・薄字で示す。
- 注記は**本文をそのまま折り返して**出す（詳細画面のようにアイコンに畳まない。読ませるのが目的）。改行は保つ（`white-space: pre-wrap`）。
  テーブル注記が無いときは「注記なし」を薄く出すが、**行では空を「注記なし」と書かない**（毎行に並ぶと読みの邪魔になる。ペンだけ残す）。
- 行の色（P-13）は詳細と同じ `data-color` で左端に出す。
- 制約・インデックス・FK・被参照・`dialect`・ビュー定義は**出さない**。それらは詳細の責務（切替で同じ位置から読める）。
- PK / FK / NULL 可否 / 型 / 既定値 / DB コメントは行から消さず、**(i) のポップアップに退避**する（R-04）。

### 2.3 ロードと描画の重さ（INV-5）

- 各セクションはマウント時に `loadTable(id)` を呼ぶ（キャッシュ済みなら即時。段階5のバックグラウンドロードで多くは読み込み済み）。
  読み込み中は見出しだけ描き、表の位置に「読み込み中」を出す。読み込み失敗（`tableErrors`）はセクション内にエラーを出し、他のセクションは描く。
- 「全て」で数百テーブルになる場合に備え、**範囲が 30 テーブル以上のときだけ**セクションに `content-visibility: auto` と `contain-intrinsic-size: auto <推定高さ>px` を付ける。
  画面外のセクションが実寸に切り替わる瞬間に境界でかくつくため、普段の範囲（1ページ分）では全部描く。
  推定高さは `index.tables[].columns`（カラム数）から出す（見出し + 行数 × 行高）。画面外のセクションはレイアウト・描画がスキップされ、
  DOM は全件持つのでアンカー・Ctrl+F は成立する。詳細の推定高さは制約・被参照の分を上乗せする。
- 詳細のセクションでは TableInfo のカラム表の高さ制限（表だけのスクロール）を外す（`fullHeight`）。文書の中に
  もう1つスクロールがあると、読み進める手が止まる。ER図のダイアログでは従来どおり制限する。
- 範囲は 1 配列なので、左パネルのフィルタ入力のたびに全セクションが再マウントされないよう、`key` はテーブル ID とする（React が並び替えとして扱う）。
- 文書の末尾に余白（`padding-bottom: 60vh`）を置く。無いと**最後のテーブルだけ見出しを上端にそろえられず**、左パネルのクリック・選択の追随が末尾で効かなくなる。
- 見出しへ移動した直後は、**その上にあるセクション**の読み込みが済むたびに合わせ直す。上のセクションは読み込みが済むと推定高さから実寸へ変わり、目的の見出しがずれるため（下のセクションは位置に影響しないので待たない）。
- スクロール追随で「読んでいる位置」が変わるたびに App・ヘッダ・左パネルが再描画される。文書本体と各セクションは `memo` にして、テーブル本体の再描画を巻き込まない（境界を越えるたびに全セクションを描き直すと、そこでかくつく）。
- 1回の `scrollIntoView` では決まらない。上のセクションは読み込み中の仮表示や `content-visibility` の推定高さで置かれ、実寸に変わると目的の見出しがずれる。目的のセクション自身が末尾でまだ小さいと、末尾で止まって届かないこともある。移動後しばらく（変化が止まって 1.5 秒）は文書の大きさの変化（`ResizeObserver`）を見張り、**こちらが置いたスクロール位置のまま**で見出しが上端から外れていれば合わせ直す。人がその間にスクロールしていれば手を出さず、ホイール・タッチ・キーの入力があれば打ち切る。
- ドキュメントのカラム表は詳細と同じ `ScrollTable`（枠・角丸・濃色ヘッダ）で描く。高さ制限は付けない。

## 3. R-02 / R-03 表示モードの切替と左パネルとの連動

### 3.1 切替と記憶（R-02）

- 切替はリンク: 詳細 `#/tables/<id>` ⇄ ドキュメント `#/tables/doc/<id>`。`<id>` は読んでいる位置のテーブルで、切替後も同じ見出しが上端に来る。着地したルートで `localStorage` の表示モードを更新する（ブックマークからの着地も含めて、**最後に使った方**を覚える）。
- `#/tables`（テーブル ID なし）は既存の `restoreTableId` を選んだうえで、記憶した表示モードのルートへ `replace` する。
- ヘッダの「テーブル」ナビも記憶した表示モードで開く（`navHref.tables`）。

### 3.2 左パネルとの連動（R-03）

| 方向 | 挙動 |
|---|---|
| 左 → 右 | 一覧のテーブルをクリック → 表示モードを保ったまま `location.hash` をそのテーブルにし、該当セクションの見出しへ `scrollIntoView`（`block: "start"`） |
| 右 → 左 | 右ペインのスクロール要素の `scroll`（rAF で間引く）で、「貼り付いたバーの下端以下にある最後の見出し」を `docActiveTableId` に書き、左パネルの選択ハイライトを追随させる。`lastTableId` も同じ値で更新する。基準をバーの下端にするのは、見出しが `scroll-margin-top` でバーの下にそろうため |

- 左パネルの `activeTableId` は、テーブル画面のルートでは URL の `<tableId>` ではなく `docActiveTableId` を渡す（App 側で出し分け）。
- **一覧側も追随する**: アクティブになった行は `scrollIntoView({ block: "nearest" })` で見える位置へ出す（`RevealLi`。すでに見えていれば一覧は動かない）。右を読み進めると左の選択が下りていき、一覧も一緒に流れる。
- URL の `<tableId>` へのスクロールは**ルートが変わったときだけ**行う（追随で `docActiveTableId` が変わっても再スクロールしない）。URL が変わったテーブルが範囲に無ければ、読んでいる位置だけをそのテーブルにする（左パネルがページを選び直す → 範囲が変わる → 見出しへ運ぶ）。
- 同じテーブルを続けてクリックしても効くよう、左パネルは URL の書き換えと別に `docScrollTo`（ID + 連番）を store に積む（同じハッシュへの代入は `hashchange` を起こさない）。
- スクロール要素はほかの画面と共用のため、**テーブル画面を離れるとき先頭へ戻す**（途中の位置を持ち越すと、次の画面が途中から開く）。

## 4. R-04 カラム属性のポップアップ

- 各行の物理名の横に (i) を置く。**ホバーでポップアップ、クリックでダイアログ**（`NotePopover` と同じ挙動・同じ見た目）。
  `NotePopover` は本文が文字列前提なので、ポップアップの機構（配置・猶予つきクローズ・フォーカス対応・ダイアログ化）を `InfoPopover` として切り出し、`NotePopover` はその薄いラッパにする。
- 中身は定義リスト:

  | 項目 | 値 |
  |---|---|
  | キー | PK / FK（参照先テーブルへのリンク。詳細画面の `TableLink`）/ ユニーク（単一カラムのユニーク・論理ユニークに含まれる場合） |
  | 型 | `type`（`logicalType` があれば併記）。auto increment / generated のバッジ |
  | NULL | 可 / 不可 |
  | 既定値 | `default` |
  | DB コメント | `comment`（DB 由来。注記とは別物なので混ぜない） |
  | タグ | 辞書 ∪ 個別（P-12） |

- 空の項目は行ごと出さない。全部空でも (i) は出す（型は常にある想定）。
- テーブル見出しにも (i) を置き、PK 構成・ユニーク / インデックス / FK の件数・DB コメント・配置ページ（リンク）を出す。
- (i) はドキュメントだけに出す（詳細は本文にすべて載っている）。

## 5. R-05 注記の直接編集

### 5.1 導線

- テーブル注記: 注記の行の右のペン。カラム注記: 行末のペン（ホバーで出す。キーボードでも到達できるよう `opacity` で隠すだけにし、DOM からは消さない）。ドキュメントモードだけに出す（詳細の編集は O-03 の編集画面）。
- **サーバーモードのみ**。静的モードではペンを出さない（O-03 と同じ）。
- テーブル編集ルート（`#/tables/<id>/edit`）で同じテーブルを編集中の可能性は考慮しない（同一タブでは遷移で排他になり、別タブは H-09 のバナーで検知する）。

### 5.2 ダイアログ

既存の `NotesDialog`（テーブル編集画面のカラム注記。複数行入力）を流用し、見出しに対象（テーブル名 / カラム名）を出す。
確定で `saveTableMeta(tableId, draft => ({ ...draft, notes }))`（カラムは `draft.columns[name].notes`）を呼ぶ。

### 5.3 保存（INV-3 / INV-4）

`saveTableMeta` の既存挙動をそのまま使う。

1. `invalidateTable` → `loadTable` で読み直し、`GET /tables/<id>` で `baseHash` を取る
2. 読み直した内容から `MetaDraft` を作り、注記だけ差し替える
3. `PUT /tables/<id>`（`force: false`）
4. 200: `rememberRevision` → `loadTable` → `reloadIndex`。store が更新され、セクションが再描画される。トースト「保存しました」
5. 409: 「他で変更されています。再読み込みしてください」（`save.staleReload`）。ダイアログは閉じ、入力は破棄する（読み直した内容が正）
6. 403 / 422 / ネットワーク: 既存のメッセージをトーストで出し、**ダイアログは開いたまま**（入力を失わせない）

書き込みは配置保存・ページ管理と同じ直列キュー（INV-6 of H）に載るため、ER図の保存と競合しない。
MCP の書き込み前バックアップ（Q-06）は MCP 経由のみの仕組みなので、ここでは取らない（GUI からの保存と同じ扱い）。

### 5.4 注記の空文字

空にして確定した場合は `notes` キーを**落とす**（`draftToMeta` の既存規則。`""` を書かない。Git 差分を汚さない）。

## 8. テスト観点

| # | 観点 | 種別 |
|---|---|---|
| 1 | `#/tables/doc/<id>` で範囲の全テーブルの見出しが出て、`<id>` の見出しが右ペインの上端に来る | e2e（静的。`e2e/doc-view-smoke.mjs`） |
| 2 | 左パネルでテーブルをクリックすると該当見出しへスクロールし、URL が `#/tables/doc/<id>` になる（詳細へ遷移しない） | e2e（静的） |
| 3 | 右ペインをスクロールすると左パネルのアクティブ行が追随する | e2e（静的） |
| 4 | 「詳細 / ドキュメント」の切替で同じテーブルが上端に来る（詳細も範囲の連続表示）。リロード後・`#/tables` からの着地でも最後のモードが復元される | e2e（静的） |
| 4b | 右をスクロールすると左パネルの選択行が見える位置へ動く | e2e（静的） |
| 5 | レーン切替・フィルタ入力で範囲が変わり、件数の見出しが一致する | e2e（静的） |
| 6 | 論理名の解決（個別 / 辞書 / 未設定）が詳細画面と一致する | unit（`logicalName` を共用しているため既存で担保）+ e2e 1件 |
| 7 | (i) のホバーでポップアップ、クリックでダイアログ。PK/FK/型/NULL/既定値/DB コメント/タグが出る | e2e（静的） |
| 8 | 注記ダイアログで確定 → ファイルに `notes` が書かれ、セクションに反映される | e2e（サーバー。`e2e/doc-notes-smoke.mjs`） |
| 9 | 注記を空にして確定 → `notes` キーが消える | e2e（サーバー） |
| 10 | 保存前に外部でファイルが変わっていても、その変更を踏み潰さない（読み直してから書く）。読み直しと PUT の間の競合（409）は `saveTableMeta` の既存経路が担う | e2e（サーバー） |
| 11 | 静的モードではペンが出ない | e2e（静的） |
| 12 | 範囲 0 件（フィルタ不一致）で空メッセージ | e2e（静的） |
