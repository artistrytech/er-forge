# ER図管理ツール 機能一覧

## 凡例

| 記号 | 意味 |
|---|---|
| **モード** | 静=静的モード（`file://`）で利用可 / 編=サーバーモードでのみ利用可 |
| **優先度** | M=MVP（必須）/ 1=v1 / 2=将来 |

**「動作モード」と「編集セッション」は別概念である。**

- **動作モード**（静的 / サーバー）は起動方法で決まり、ユーザーは切り替えられない。上表の「モード」列はこれを指す。
- **編集セッション**（閲覧中 / 編集中）はユーザーが明示的に切り替える（H-10）。**静的モードでも編集操作はできる**が、保存はできず、H-13 のエクスポートで持ち出す。「静・編（保存は編）」と書かれた機能がこれにあたる。

「ER図」と「テーブルカタログ」は対等な2つのビューである。**ER図はテーブル間の関係の俯瞰に責務を限定し、テーブルの中身（カラム・制約）はカタログ側で扱う。**

**このツールはローカルで単独利用する前提である。** 複数人による同時編集は考慮しない（競合は保存時に検出して中止し、人が再操作すれば復旧できる設計とする。H-12）。

**スキーマ（ネームスペース）は単一である。** 対象スキーマは逆生成の設定（K-06）でのみ指定し、GUI にスキーマ名は表示しない。

## A. 起動・モード

| ID | 機能 | 概要 | モード | 優先度 |
|---|---|---|---|---|
| A-01 | モード自動判定 | `/__erd/health` の疎通で静的/サーバーを判定し、編集UIの表示を切り替える | 静・編 | M |

| A-05 | 欠損ファイル警告 | ロードに失敗したテーブルを一覧で通知（該当ノードはエラー表示） | 静・編 | M |

| A-07 | オンボーディング | 初回起動時にセットアップ手順（DB接続 → 逆生成 → 配置 → commit）をガイド | 編 | 2 |
| A-08 | 空プロジェクトの初期化（ブートストラップ） | ワークスペースが0件なら welcome 画面で作成させ（A-10）、そのうえで `data/**` が無い / テーブル0件なら初期化方法を選ばせる。**①既存のスキーマから生成する**（DB接続 → 逆生成）/ **②サンプルデータを取り込む**（約30テーブルの完成済みサンプルを書き出す。DB なしで機能を試せる）/ ③（将来）空のプロジェクトを作成し手動でテーブルを作る（J-01 実装後に追加）。既存データがある場合、サンプルの取り込みは実行できない。静的モードでデータが空なら「サーバーモードで起動して初期化してください」と表示する | 編 | M |
| A-09 | データ形式の自動移行 | `manifest.schemaVersion` がサーバーの版より古ければ、**起動時に全ワークスペースを走査して自動で移行する**（バックアップ → 全ファイルを新形式で再生成 → アトミック置換）。完了後「v1 → v2 に移行しました。単独のコミットにすることを推奨します」と通知する。データの方が新しいワークスペースには**一切触れず、サーバーの起動は続ける**（そのワークスペースだけがバナー表示になる。1つの不整合で全体が起動しないのを避ける） | 編 | M |
| A-10 | ワークスペース（マルチデータベース構成） | 1ワークスペース = 1DB。実体は `erd/workspace-<id>/data/**`。**アプリタイトル横のプルダウン**で切り替え（フルリロード）・追加でき、ID（英数・ハイフン・アンダーバー。省略時 `default`）と表示名（必須）を持つ。ID は後から変更でき、フォルダ名も追随する（Git 上は削除＋追加）。削除は設定メニューから行い、**確認に ID の打ち込みを求める**（データリセットとは別物で、リセットは現在のワークスペースのスキーマ情報だけを消す）。JDBC ドライバの設定は全ワークスペース共通。URL は `#/w/<id>/…`。**横断検索・ワークスペース間コピーは対象外** | 静（切替のみ）・編 | M |
| A-11 | 閲覧用 ZIP の書き出し | **GUI（ツールメニュー）と CLI（`erd export`）の両方**から行う。`index.html`・`workspaces.js`・選んだ `workspace-*/data/**`・`THIRD-PARTY-NOTICES.txt` を `<prefix>-<timestamp>.zip` にまとめる。**`workspaces.js` は選択に合わせて作り直す**（そのまま入れると、書き出さなかったワークスペースがプルダウンに並んで壊れる）。**個人データ（`.local/`）・`erd-server.jar`・`drivers/`・ルートの `config.js` は入れない**（接続情報が混ざると事故になるため、除外はテストで固定する）。**ファイル名のプレフィックス**は任意（ファイル名に使えない文字だけを弾く。検査の正はサーバー）、**含めるワークスペース**は選択式（既定は全部）。GUI には選択と等価な CLI コマンドを常に表示してコピーできるようにする。ZIP を組み立てるのは両経路とも同じコード（`ViewerExport`）で、GUI は `POST /__erd/export/viewer` を呼ぶだけ。設計書 §3.2 | 編 | M |

## D. テーブルノードの表現

> **ノードはテーブル名のみを描画する。カラム・型・制約などの詳細情報はノードに描かない。**
> 詳細はノードのダブルクリック（詳細ダイアログ）と、テーブルカタログ（O）で参照する。

| ID | 機能 | 概要 | モード | 優先度 |
|---|---|---|---|---|
| D-01 | ノード表示 | テーブルの論理名 / 物理名（表示方法は P-05 で切替）を表示する。**スキーマ名は表示しない**（単一スキーマ前提）。カラム行は描画しない | 静・編 | M |
| D-02 | ノード幅の調整 | 名前が長い場合に端をドラッグして幅を変更（`w` として保存）。省略時は内容に合わせて自動 | 編 | 1 |
| D-03 | ノードの色分け | `meta.color`（指定色）でノードを着色する。**タグとは連動しない**（P-13）。色は `index.js` に載るため静的モードでも効く。MiniMap も同じ色で塗る。**欠損の警告色・選択枠は指定色より優先**し、減光（不透明度）とは表現軸を分ける | 静・編（設定は編） | M |
| D-04 | 注記アイコン | `meta.notes` があるテーブルにアイコンを表示（ホバーで内容） | 静・編 | 1 |
| D-05 | エラーノード表示 | ファイル欠損・参照先不明のテーブルを警告色で表示 | 静・編 | M |
| D-06 | ノードのダブルクリック → 詳細ダイアログ | テーブル詳細を**閲覧専用のダイアログ**で表示する（G-01） | 静・編 | M |
| D-07 | ビュー等のノード表現 | `kind` が `TABLE` 以外のオブジェクト（ビュー・マテリアライズドビュー等）を**破線枠**と**種別バッジ**（DB が返した種別名の原文）で区別する。**種別による自動着色はしない**（色は human-owned。D-03）。ビューは FK を持たないため既定では孤立ノードになり、関係を描きたい場合は論理外部制約（P-06）を人が定義する（K-16） | 静・編 | M |

> **詳細設計（編集画面）: [O-03・O-08・J-01〜J-06 テーブル編集画面の保存モデル](function-details/O03-O08_J01-J07_table-edit.md)**

| ID | 機能 | 概要 | モード | 優先度 |
|---|---|---|---|---|
| O-01 | テーブル一覧画面（`#/tables`） | 全テーブルを表形式で表示（物理名・論理名・カラム数・PK・所属ページ・タグ）。列でのソート、タグ / 語句による絞り込み。**各行はテーブル詳細への実リンク** | 静・編 | M |
| O-02 | テーブル詳細画面（`#/tables/<id>`） | 1テーブルの全情報を表示：カラム表（物理名・論理名・型・NULL・デフォルト・コメント・**タグ**・注記。**指定色のあるカラムは行を着色**）、PK / ユニーク / インデックス / FK、**論理一意制約 / 論理外部制約**、被参照一覧、`meta`、`dialect`。参照先・参照元テーブルはリンク | 静・編 | M |
| O-03 | テーブル編集画面（`#/tables/<id>/edit`） | 詳細画面から遷移する**唯一の編集入口**。カラム・制約（J-03 / J-04）、テーブル論理名（P-01）、カラム論理名の個別設定（P-04）、論理制約（P-06 / P-07）、タグ（P-12。テーブル / カラム）・色（P-13。テーブル / カラム）・注記を編集して保存する。**自動保存はせず**、明示的な [保存] / `Cmd/Ctrl + S` でのみ書き込む。**物理名の変更はリネームとして扱い**、ER図の配置・論理名・他テーブルの参照を引き継ぐ（J-03 / J-04）。静的モードでは詳細画面へリダイレクトし、閲覧モードである旨を表示 | 編 | M |

| O-05 | 型表示の切替 | 物理型（`type`）と論理型（`logicalType`）の表示を切り替える | 静・編 | 1 |
| O-06 | DDL プレビュー | スキーマ情報から `CREATE TABLE` 相当を生成して表示・コピー | 静・編 | 2 |
| O-07 | 一覧の未整備ハイライト | 論理名が未設定のテーブル / カラムを持つ行を目立たせ、整備すべき箇所を可視化する | 静・編 | 1 |
| O-08 | 編集の保存とバリデーション | 保存前に検証（J-06 / P-08）し、エラーがあれば該当フィールドに表示して保存を中断する。保存後は詳細画面へ戻る | 編 | M |

## P. 論理名・論理制約

> **詳細設計: [P-01〜P-09 論理名・論理制約](function-details/P01-P09_logical-names-constraints.md)**
> 論理名の解決関数と表示切替、一括編集画面（行集合・孤立エントリ・一括貼り付け・ロードとの関係）、コメント補完の条件と切り出し規則、論理制約の効果と `index.js` の再生成トリガ、エッジID の名前空間、バリデーション、テスト観点。

> DB のスキーマには存在しない、**人が付与する意味情報**。`meta` と `dictionary.js` に保持し、逆生成では失われない（K-14 の初期値補完を除き、逆生成は `meta` を書き換えない）。

| ID | 機能 | 概要 | モード | 優先度 |
|---|---|---|---|---|
| P-01 | テーブル論理名 | テーブル編集画面（O-03）から設定する（`meta.displayName`）。逆生成した場合は DB コメントから初期値が復元される（P-02） | 編 | M |
| P-02 | コメントからの論理名復元 | 逆生成の適用時、論理名が未設定のテーブル / カラムに限り DB コメントの1行目を初期値とする。既存値は上書きしない（K-14） | 編 | M |
| P-03 | カラム辞書（`#/columns`） | **テーブルを超えてカラムの共通設定を一律に編集する専用画面。** カラム物理名ごとの論理名・タグ・色（`dictionary.js`）を表形式で編集する。論理名・タグ・色は**すべて行内で編集する**（数百行を上から埋める作業のため）。行数に耐えるよう一覧は**仮想化**し、行高を固定してタグは折り返さない。内訳（出現テーブル / 個別設定のあるテーブル）の確認は行の [🔍] から開く**詳細ダイアログ**で行う。孤立エントリ（どのテーブルにも無い物理名）だけは一覧に警告バッジを残し、理由はダイアログで説明する。語句・タグでの絞り込みが可能。**閲覧（`#/columns`）と編集（`#/columns/edit`）を分け、[編集開始] で編集モードに入る**。編集中はダイアログ内のテーブルへのリンクを非活性にする。**静的モードでは閲覧のみ**（辞書を読み取り表示し、[編集開始] は出さない） | 静・編 | M |
| P-04 | カラムの個別設定 | テーブル編集画面（O-03）で、カラム単位に論理名・色を設定してカラム辞書を上書きする（`meta.columns.<name>`）。辞書と異なる値であることを画面上で明示する。**共通タグは読み取り専用のチップとして出し、個別からは取り消せない**（P-12） | 編 | M |
| P-05 | 論理名の解決と表示切替 | 解決順序は「個別設定 → カラム辞書 → 物理名」（色も同じ順。タグだけは辞書と個別の**合成**）。表示は「論理名 / 物理名 / 併記」を切り替えられる（既定は併記）。ER図ノード・一覧・詳細・検索のすべてで同じ解決結果を使う | 静・編 | M |
| P-06 | 論理一意制約 | DB に制約は無いが運用上一意である組を `meta.logicalUniques` として設定・表示する。物理ユニーク制約とは視覚的に区別して表示する（カーディナリティ判定にも使用） | 編（表示は静・編） | M |
| P-07 | 論理外部制約 | DB に FK は無いが論理的には参照関係にある組を `meta.logicalForeignKeys` として設定・表示する。**ER図には破線エッジとして描画される**（E-09）。参照先テーブル・カラム、注記を保持する | 編（表示は静・編） | M |
| P-08 | 論理制約のバリデーション | 参照先テーブル / カラムの存在、カラム数の一致、自テーブルのカラムの存在を保存時に検証する。既存の物理制約と重複する場合は警告する | 編 | 1 |
| P-09 | 論理制約の一覧 | 整合性チェック（M-04）で、参照先を失った論理制約を一覧表示する | 静・編 | 1 |
| P-10 | 辞書への昇格提案 | 同名カラムの DB コメントが**出現する全テーブルで一致している**場合、それはプロジェクト共通の意味とみなせる。カラム辞書の画面（P-03）で「辞書に昇格できる候補が N 件あります」と提示し、承認すれば辞書へ集約して各テーブルの個別設定を削除する | 編 | 1 |
| P-11 | カーディナリティの設定 | リレーションの多重度を `meta.relations` に設定する。**物理情報から導出できない多重度**（親から見た子の下限が 0 か 1 か = `0..N` か `1..N` か）は業務ルールであり、人が設定するしかない。既定は「自動（物理から導出）」で、テーブル編集画面（O-03）の FK / 論理外部制約の行、およびリレーション詳細ダイアログ（E-10）から上書きする。根拠（notes）も保持し、手動設定であることを画面上で明示する | 編（表示は静・編） | M |
| P-12 | タグ | テーブル（`meta.tags`）・カラム（`meta.columns.<name>.tags`）・カラム辞書（`dictionary.columns.<name>.tags`。**同名カラム全体に一律で付く**）に**同じ名前空間**のタグを付ける。共通タグは個別設定からは取り消せず、表示では個別タグと合成される（重複はまとめる）。**分類・検索のためのもので、見た目（色）には一切影響しない**（色は P-13）。入力はチップ形式で、**半角 / 全角スペース・Enter・カンマ・Tab・フォーカスアウトで確定**する。**IME 変換中は確定しない**（日本語タグを打つと必ず踏むため）。候補は `index.js` の `tagsUsed`（使用中タグの集合。テーブル未ロードでも引ける）＋ カラム辞書の共通タグ（`index.js` には載せない）から出す。タグ名は空白・区切り文字（`,` `、`）を含めず、32文字以内・1要素あたり20個以内。前後空白・空要素・重複（大小無視）は保存時に正規化する。**順序に意味は無い**（人の書いた順は保つ） | 編（表示は静・編） | M |
| P-13 | 色の指定 | テーブル（`meta.color`）・カラム（`meta.columns.<name>.color`）・カラム辞書（`dictionary.columns.<name>.color`。**同名カラム全体に一律で付き、個別設定で上書きできる**）に色を直接指定する。**タグとは独立**で、タグから色を導出する仕組みは持たない（「廃止」タグを付けても自動ではグレーにならない。意味はタグで、見た目は色で表す）。指定できるのは**用意されたトークンのみ**（`gray` `red` `amber` `green` `blue` `purple` `muted`）で、任意の hex は許さない（配色の一貫性とコントラストを壊さないため）。UI は**現在の色の丸を押すとポップアップで選ぶ**方式（一覧の行に8個並べると幅もボタン数も破綻する）。`muted` がグレーアウト用。**テーブルの色はカラムに継承しない**（継承するのはカラム辞書 → 同名カラムだけ。カラム名からの自動割り当ても行わない）。未知のトークンは既定の外観で描画しつつ値は保持する（サーバーは 422 で拒否） | 編（表示は静・編） | M |

## MVP スコープ（機能の絞り込み）

上記のうち優先度 **M** のみを実装した状態で、以下の一連の体験が成立する。

1. 編集者が Release を展開して `java -jar erd-server.jar` を起動する
2. JDBC URL で DB に接続し、逆生成を実行して差分を確認・適用する（このとき DB コメントからテーブル・カラムの論理名の初期値が復元される）
3. 新規テーブルが未配置トレイに入るので、ページを作成して配置し、ドラッグで整える
4. カラム辞書（`#/columns`）で、`created_at` などの共通カラムの論理名・タグ・色をまとめて整える。テーブル固有のものは各テーブル編集画面で上書きする
5. DB に制約が無い一意性・参照関係を、論理一意制約 / 論理外部制約として登録する（ER図に破線エッジとして現れる）
6. `index.html`・`workspaces.js`・`workspace-*/data/**` をコミットする
7. メンバーが pull して `index.html` を開き、ページを切り替え、検索し、リレーションを追跡して閲覧する。ノードをダブルクリックしてテーブル詳細を見て、そこからテーブル詳細画面へリンクで移動する（Ctrl+クリックで別タブに開ける）
8. UI は各メンバーの環境設定に応じて日本語 / 英語で表示される
9. 再度の逆生成でスキーマが更新されても、ER図の配置・論理名・論理制約・注記は保持される
